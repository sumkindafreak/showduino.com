CURRENT HARDWARE STACK

Built around
real roles.

The Showduino hardware stack now follows the same architecture as the software: dedicated devices for operator control, communications, runtime authority and physical outputs.

DIRECTOR

ESP32-S3 800×480 touchscreen

The Director is the operator-facing controller. The current hardware uses an ESP32-S3 touchscreen platform with a large 800×480 display for live show controls and status.

  • RoleOperator requests and state display
  • Primary linkESP-NOW to the Communications Controller
  • Runtime authorityNo — the P4 remains authoritative
COMMS CONTROLLER

Dedicated ESP32-S3 bridge

The previous C3 bridge concept has been superseded by a full ESP32-S3 Communications Controller. It bridges wireless traffic to the P4 without making show decisions.

  • WirelessESP-NOW
  • P4 transportUART 115200 8N1
  • Show logicNone by design
SHOW ENGINE

Waveshare ESP32-P4-Module-DEV-KIT

The P4 is the centre of the live runtime: state, safety, cue dispatch, timeline execution, local storage and Showduino system services.

  • Comms UARTRX GPIO4 · TX GPIO5
  • I²C plug-in busSDA GPIO7 · SCL GPIO8 · 100 kHz
  • Status LEDGPIO10
  • Emergency inputGPIO25
  • I²S system audioWS GPIO20 · BCLK GPIO21 · DATA GPIO22
  • Pixel lineGPIO24
  • StorageSD card for projects/assets
  • Onboard C6Reserved / unused in current architecture
SPECIALIST NODES

Output hardware follows the job.

Instead of forcing every effect through one generic box, Showduino uses specialist nodes that can be built, tested and diagnosed around the load they actually control.

RLY

Relay Node

For compatible switched outputs and devices that benefit from isolated relay control.

MOS

MOSFET Node

For suitable low-voltage loads where solid-state switching makes more sense than a mechanical relay.

PIX

Pixel Node

For segmented addressable LED effects and emergency-white override behaviour.

AUD

Audio Node

For dedicated show audio playback, separate from the P4's own local system sounds.

EXPANSION

I²C without turning the P4 into a wiring mess.

The P4 exposes a defined plug-in bus for supported I/O and PWM expansion hardware. The current architecture keeps expansion modular instead of scattering one-off pin assignments throughout the build.

MCP23017

General-purpose digital I/O expansion for compatible plug-in hardware.

PCA9685

PWM/servo-style expansion where dedicated multi-channel PWM is useful.

TCA9548A

I²C multiplexing where multiple same-address devices or isolated branches are required.

Current scope note: DMX is deliberately not part of the current Showduino implementation plan. The present focus is finishing the relay, MOSFET, pixel, audio, storage and runtime path properly before opening another protocol.
